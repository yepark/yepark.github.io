# 머신러닝 기초
{: .no_toc }

{% include article-toc.md %}

스팸 메일을 거르는 프로그램을 만든다고 생각해 보자. 처음에는 `if "무료" in 제목` 같은 규칙을 쓴다. 그런데 스팸은 금방 단어를 바꾸고, 정상 메일에도 "무료 배송"이 들어간다. 규칙은 계속 늘어나고 서로 충돌한다.

**머신러닝**은 규칙을 사람이 쓰는 대신, 정답이 붙은 예시를 보여 주고 프로그램이 규칙을 찾게 하는 방법이다. 사람이 정하는 것은 "무엇을 입력으로 주고, 무엇을 맞히게 하고, 얼마나 틀렸는지를 어떻게 잴지"다.

## 일반 프로그래밍과 무엇이 다른가

| | 일반 프로그래밍 | 머신러닝 |
| --- | --- | --- |
| 사람이 주는 것 | 규칙 + 입력 | 입력 + 정답 예시 |
| 프로그램이 내놓는 것 | 결과 | 규칙(학습된 모델) |
| 틀렸을 때 고치는 곳 | 코드 | 데이터, 모델 구조, 학습 설정 |

그래서 머신러닝 프로젝트에서 시간이 가장 많이 드는 곳은 보통 모델 코드가 아니라 데이터다. 정답이 잘못 붙어 있거나, 실제 사용 환경과 다른 데이터로 학습하면 모델은 그 잘못을 그대로 배운다.

## 학습을 이루는 네 가지

어떤 모델이든 학습은 다음 네 가지로 설명할 수 있다.

1. **데이터**: 입력(특징, feature)과 정답(레이블, label)의 쌍. 메일 본문과 "스팸/정상" 표시가 한 쌍이다.
2. **모델**: 입력을 받아 예측을 내놓는 함수. 내부에 조정 가능한 숫자(파라미터)가 있다. `y = w·x + b`에서는 `w`와 `b`가 파라미터다.
3. **손실 함수**: 예측이 정답과 얼마나 다른지를 하나의 숫자로 잰다. 숫자가 작을수록 잘 맞힌 것이다.
4. **최적화**: 손실이 줄어드는 방향으로 파라미터를 조금씩 바꾼다. 대표적인 방법이 경사 하강법이다.

학습이란 결국 "손실을 재고, 파라미터를 조금 바꾸고, 다시 재는" 반복이다. 이 반복을 직접 코드로 보고 싶다면 [Mac에서 TensorFlow 실습]({{ '/ai/using-ai/tensorflow-mac/' | relative_url }})의 학습 루프 예제를 보면 된다.

## 학습의 종류

| 종류 | 데이터 | 예시 |
| --- | --- | --- |
| 지도 학습 | 입력 + 정답 | 스팸 분류, 집값 예측, 손글씨 숫자 인식 |
| 비지도 학습 | 입력만 | 고객 군집 나누기, 이상 거래 찾기 |
| 강화 학습 | 행동에 대한 보상 | 게임 플레이, 로봇 제어 |

지도 학습은 다시 두 가지로 나뉜다. 정해진 범주 중 하나를 고르면 **분류**(스팸/정상), 숫자를 맞히면 **회귀**(집값)다. 이 구분에 따라 손실 함수와 평가 지표가 달라진다.

## 데이터를 나누는 이유

모델이 학습에 쓴 데이터를 잘 맞히는 것은 당연하다. 알고 싶은 것은 **처음 보는 데이터**를 얼마나 잘 맞히느냐다. 그래서 데이터를 세 묶음으로 나눈다.

| 묶음 | 용도 |
| --- | --- |
| 학습(train) | 파라미터를 조정하는 데 사용 |
| 검증(validation) | 모델 구조나 학습 설정을 고르는 데 사용 |
| 테스트(test) | 마지막에 한 번, 최종 성능을 재는 데 사용 |

테스트 데이터를 보고 설정을 여러 번 바꾸면 테스트 데이터에 맞춰진 설정을 고르게 된다. 그러면 테스트 점수가 실제 성능보다 좋게 나온다. 테스트 데이터는 끝까지 아껴 둔다.

나눌 때 주의할 점이 하나 더 있다. 학습 데이터에 테스트 데이터의 정보가 섞이는 **데이터 누수**다. 같은 사용자의 메일이 학습과 테스트 양쪽에 들어가거나, 전체 데이터로 평균을 구해 정규화한 뒤 나누는 경우가 흔한 예다. 누수가 있으면 평가 점수는 좋은데 실제 서비스에서는 성능이 떨어진다.

## 과소적합과 과적합

모델이 너무 단순하면 학습 데이터의 패턴도 잡지 못한다(**과소적합**). 너무 복잡하면 학습 데이터의 잡음까지 외워서 새 데이터에서 틀린다(**과적합**).

다항식 차수를 바꿔 가며 확인해 보자. `sin` 곡선에 잡음을 섞은 점 20개 중 14개로 학습하고 6개로 테스트한다.

```python
import numpy as np
import warnings
warnings.simplefilter("ignore", np.exceptions.RankWarning)

rng = np.random.default_rng(0)
x = np.sort(rng.uniform(0, 1, 20))
y = np.sin(2 * np.pi * x) + rng.normal(0, 0.2, x.size)

idx = rng.permutation(x.size)
train, test = idx[:14], idx[14:]

def mse(coef, i):
    return np.mean((np.polyval(coef, x[i]) - y[i]) ** 2)

for degree in (1, 3, 12):
    coef = np.polyfit(x[train], y[train], degree)
    print(f"degree={degree}  train MSE={mse(coef, train):.3f}  test MSE={mse(coef, test):.3f}")
```

NumPy 2.5에서 실행한 결과다.

```
degree=1  train MSE=0.240  test MSE=0.175
degree=3  train MSE=0.012  test MSE=0.012
degree=12  train MSE=0.000  test MSE=0.052
```

- **1차(직선)**: 학습 오차부터 크다. 곡선을 직선으로 맞추려 했기 때문이다. 과소적합이다.
- **3차**: 학습과 테스트 오차가 모두 작고 비슷하다.
- **12차**: 학습 오차는 0에 가깝지만 테스트 오차는 3차보다 4배 이상 크다. 점 14개를 거의 그대로 지나가도록 외웠기 때문이다. 과적합이다.

학습 오차만 보면 12차가 가장 좋아 보인다. 테스트 오차를 같이 봐야 3차를 고를 수 있다. 실제 프로젝트에서는 이 비교를 검증 데이터로 하고, 테스트 데이터는 최종 확인에만 쓴다.

과적합을 줄이는 방법은 대체로 세 갈래다.

- 데이터를 늘린다.
- 모델을 단순하게 하거나 규제(정규화, 드롭아웃)를 건다.
- 검증 손실이 더 나아지지 않으면 학습을 멈춘다(조기 종료).

## 평가 지표 고르기

분류 모델의 가장 쉬운 지표는 **정확도**(맞힌 비율)다. 하지만 클래스 비율이 치우치면 정확도는 쉽게 속인다. 메일의 1%만 스팸이라면, 모든 메일을 "정상"이라고 답하는 모델도 정확도가 99%다.

| 지표 | 질문 | 중요한 경우 |
| --- | --- | --- |
| 정밀도(precision) | 스팸이라고 한 것 중 진짜 스팸은 얼마나 되나 | 정상 메일을 스팸함에 넣으면 곤란할 때 |
| 재현율(recall) | 진짜 스팸 중 몇 개를 잡았나 | 놓치면 위험할 때 (사기 거래, 질병) |
| F1 | 정밀도와 재현율의 조화 평균 | 둘 다 균형 있게 볼 때 |

회귀에서는 평균제곱오차(MSE)나 평균절대오차(MAE)를 쓴다. 어떤 지표가 맞는지는 모델이 틀렸을 때 생기는 비용으로 정한다.

## 머신러닝과 LLM 프롬프트 중 무엇을 쓸까

요즘은 분류 작업도 LLM에 프롬프트로 맡길 수 있다. 둘 중 하나를 고를 때는 다음을 본다.

| 기준 | 직접 학습한 모델이 유리 | LLM 프롬프트가 유리 |
| --- | --- | --- |
| 정답 데이터 | 수천 건 이상 있음 | 거의 없음 |
| 요청량과 비용 | 많고, 빠르고 싸야 함 | 적거나 가끔 |
| 입력 형태 | 숫자, 이미지, 고정된 형식 | 자유로운 문장 |
| 기준 변경 | 드묾 | 자주 바뀜 |

두 방법 모두 평가 데이터로 성능을 재야 한다는 점은 같다. 프롬프트 쪽 방법은 [프롬프트 엔지니어링]({{ '/ai/using-ai/prompt-engineering/' | relative_url }})과 [평가]({{ '/ai/using-ai/evaluation/' | relative_url }})에서 다룬다.
