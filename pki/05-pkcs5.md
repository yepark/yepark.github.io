# PKCS #5: 패스워드 기반 암호와 PBKDF2
{: .no_toc }

{% include article-toc.md %}

PKCS #5는 사람이 입력한 패스워드로 암호 키를 만들고 데이터를 암호화하거나 인증하는 방법을 정의한다. 현재 기본 문서는 **RFC 8018, PKCS #5 v2.1**이다.

## 패스워드에서 암호 키를 만들기

사람이 기억하는 패스워드와 암호 알고리즘이 요구하는 고정 길이 키는 다르다. KDF는 패스워드에 salt와 연산 비용을 적용해 필요한 키 바이트를 만드는 함수다.

salt는 같은 패스워드라도 다른 결과가 나오게 하는 입력이며 보통 비밀이 아니다. 반복 횟수는 공격자가 후보를 시험하는 비용과 사용자 대기 시간을 함께 바꾼다. 코드의 예전 기본값을 그대로 선택하기보다 현재 기기와 정책에 맞춰 측정해야 한다.

## 패스워드를 AES 키로 바로 쓰면 안 되는 이유

사람의 패스워드는 길이와 분포가 불규칙하고 추측 가능한 경우가 많다. 공격자는 유출된 암호문을 가지고 후보 패스워드를 대량으로 시험할 수 있다.

KDF(Key Derivation Function)는 salt와 반복 비용을 사용해 후보 하나를 시험하는 비용을 높이고 필요한 길이의 키를 만든다.

## PBKDF2

```text
DK = PBKDF2(PRF, Password, Salt, IterationCount, KeyLength)
```

- `PRF`: 의사난수 함수(입력이 같으면 늘 같은 결과를 내지만 겉보기에는 무작위인 값을 만드는 함수). 보통 HMAC-SHA256을 쓴다
- `Password`: 사용자 패스워드의 정확한 바이트 표현
- `Salt`: 각 데이터마다 새로 생성하는 무작위 값
- `IterationCount`: 반복 비용
- `KeyLength`: 필요한 파생 키 길이

salt는 비밀이 아니며 암호문 옆에 저장할 수 있다. 같은 패스워드라도 salt가 다르면 다른 키가 나온다. 그래서 흔한 패스워드의 결과를 미리 계산해 둔 표(레인보우 테이블)를 쓸 수 없고, 두 사용자가 같은 패스워드를 쓰는지도 드러나지 않는다.

반복 횟수는 영원히 고정된 안전값이 아니다. 대상 기기에서 허용 가능한 지연을 측정하고 정책과 위협 모델에 맞춰 조정해야 한다.

## PBES2

PBES2는 두 부분을 조합한다.

1. PBKDF2 같은 KDF로 패스워드에서 키를 만든다.
2. 선택한 대칭 암호 방식으로 데이터를 암호화한다.

ASN.1의 알고리즘 식별자 안에는 KDF 파라미터와 암호화 방식의 파라미터가 들어간다. 복호화하려면 salt, 반복 횟수, PRF, IV(Initialization Vector, 암호화를 시작할 때 섞는 무작위 값) 같은 값을 정확히 보존해야 한다.

## PBMAC1

패스워드에서 MAC 키를 만든 뒤 메시지 인증 코드(MAC)를 계산한다. MAC은 키를 아는 사람만 만들 수 있는 짧은 검사값이다. 암호화가 기밀성을 위한 것이라면 MAC은 변조와 키 보유 여부 확인을 위한 것이다.

## 패스워드 저장과 파일 암호화를 구분하자

로그인 패스워드 검증용 저장에는 복호화 가능한 암호가 필요하지 않다. Argon2id, scrypt, bcrypt 같은 패스워드 저장 전용 해시 알고리즘을 쓴다. 이 알고리즘들은 계산뿐 아니라 메모리도 많이 쓰게 만들어 GPU로 대량 추측하기 어렵게 한다. PKCS #5는 개인 키 파일처럼 나중에 복호화해야 하는 데이터를 패스워드로 보호하는 문맥에서 자주 만난다.

## 구현 원칙

- salt를 고정하거나 재사용하지 않는다.
- 패스워드 문자열의 문자 인코딩 규칙을 상호 합의한다.
- 오래된 DES·RC2 기반 예제를 새 설계에 복사하지 않는다.
- 인증되지 않은 암호 방식이면 변조 검증 방법을 별도로 갖춘다.
- 파라미터와 알고리즘 식별자를 암호문과 함께 보존한다.
- 라이브러리의 고수준 API와 현재 플랫폼 보안 지침을 따른다.

## 패스워드를 맞게 입력했는데 복호화가 실패한다면

두 프로그램이 화면에서 같은 패스워드를 받았어도 실제 입력 바이트가 같다는 보장은 없다. 문자 인코딩이나 정규화가 다르면 KDF 입력이 달라진다. 다음으로 salt, 반복 횟수, PRF, 출력 길이를 비교한다. 어느 하나가 달라도 다른 키를 얻는다.

```text
패스워드 바이트 + salt + KDF 파라미터
  → 파생 키
  → 암호 알고리즘 + IV/nonce + 암호문
  → 복호화 결과 및 무결성 확인
```

salt와 IV는 목적이 다르다. salt는 패스워드에서 키를 만드는 단계에, IV/nonce는 암호 연산에 들어간다. 같은 필드로 합쳐 생각하면 포맷을 잘못 해석하기 쉽다. 필요한 값은 비밀 여부와 별개로 정확히 저장해야 한다.

## 반복 횟수를 높여도 생기지 않는 것

반복은 추측 한 번의 계산 비용을 늘린다. 약한 패스워드의 후보 수 자체를 늘리거나 유출된 패스워드를 되돌려 비밀로 만들지는 않는다. 또한 파일에 기록된 반복 횟수를 제한 없이 받아들이면 공격자가 과도한 값을 넣어 서비스 자원을 소모시킬 수 있으므로 읽는 쪽의 자원 한계도 필요하다.

[RFC 8018 §4](https://www.rfc-editor.org/rfc/rfc8018.html#section-4)는 salt와 반복 비용, §5.2는 PBKDF2, §6.2는 PBES2를 다룬다. 먼저 키 파생과 데이터 암호화를 구분한 뒤 각 파라미터가 어디에 들어가는지 따라 읽자.
