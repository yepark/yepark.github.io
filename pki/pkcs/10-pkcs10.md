# PKCS #10: 인증서 서명 요청 CSR

PKCS #10은 인증기관(CA)에 인증서 발급을 요청할 때 쓰는 CSR(Certificate Signing Request)의 문법을 정의한다. 현재 문서는 **RFC 2986**이다.

## CSR 구조

```asn1
CertificationRequest ::= SEQUENCE {
    certificationRequestInfo CertificationRequestInfo,
    signatureAlgorithm       AlgorithmIdentifier,
    signature                BIT STRING
}
```

안쪽 `CertificationRequestInfo`에는 다음이 들어간다.

- 버전: 현재 `0`
- Subject DN: 발급받을 주체 이름
- SubjectPublicKeyInfo: 공개 키 알고리즘과 공개 키
- Attributes: 추가 요청 정보

요청자는 이 전체 정보에 대응하는 개인 키로 서명한다.

## CSR 서명이 증명하는 것

CSR 서명을 포함된 공개 키로 검증하면 요청자가 대응하는 개인 키를 보유했다는 사실을 확인할 수 있다. 하지만 다음을 자동으로 증명하지는 않는다.

- Subject 이름이 실제 사람·회사와 일치함
- 요청한 DNS 도메인을 통제함
- 요청한 용도가 정책상 허용됨
- 공개 키가 안전하게 생성·보관됨

이 검증은 CA의 신원 확인과 도메인 검증, 발급 정책이 담당한다.

## extensionRequest

PKCS #9의 `extensionRequest` 속성을 사용해 인증서에 넣고 싶은 X.509 v3 확장을 요청할 수 있다.

```text
Subject Alternative Name: example.com, www.example.com
Key Usage: Digital Signature
Extended Key Usage: TLS Web Server Authentication
```

CA는 요청을 검토하고 정책에 따라 최종 인증서 내용을 결정한다.

## PEM 표현

```text
-----BEGIN CERTIFICATE REQUEST-----
Base64로 인코딩된 DER
-----END CERTIFICATE REQUEST-----
```

PEM은 전달 표현일 뿐이며 핵심 구조는 안쪽 DER이다. CSR에는 개인 키가 들어가지 않는다.

## CA가 검증할 항목

1. ASN.1과 DER 구조가 유효한가
2. CSR 서명이 포함된 공개 키로 검증되는가
3. 키 알고리즘과 키 크기가 정책을 만족하는가
4. Subject DN과 요청 확장이 허용되는가
5. 이름과 신원 검증 절차를 통과했는가
6. 중복·알 수 없는 속성을 안전하게 처리하는가

Subject DN과 국내 프로파일은 [PKCS#10 인증서 서명 요청과 Subject DN]({{ '/pki/pkcs10-subject/' | relative_url }})에서 더 자세히 설명한다.
