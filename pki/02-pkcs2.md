# PKCS #2: 폐기된 RSA 메시지 다이제스트 규격
{: .no_toc }

{% include article-toc.md %}

PKCS #2는 RSA 암호와 함께 사용할 메시지 다이제스트를 다루던 초기 규격이다. 이 규격은 **1990년대에 PKCS #1로 흡수돼 폐기**됐다.

## 폐기된 번호도 알아두는 이유

오래된 연동 문서에는 현재 사용하지 않는 표준 이름이 남을 수 있다. PKCS 번호는 학습 단계나 보안 등급이 아니라 서로 다른 규격을 식별하는 이름이다.

이 편에서는 구현 방법보다 역사적 규격이 어디로 통합됐는지 확인한다. 메시지 다이제스트는 원문의 지문에 비유할 수 있지만, 누구나 계산할 수 있어 그것만으로 작성자를 증명하지는 못한다.

## 메시지 다이제스트란

길이가 제각각인 메시지를 해시 함수에 넣어 얻은 고정 길이 값이다. 원문이 한 글자만 바뀌어도 결과가 완전히 달라지고, 결과에서 원문을 되돌려 알아낼 수 없다.

```text
긴 메시지 ──해시 함수──▶ 고정 길이 다이제스트
```

전자서명은 보통 원문 전체에 RSA 연산을 하지 않고 메시지 해시를 정해진 서명 인코딩에 넣는다. PKCS #2가 별도 번호로 다뤘던 영역은 이후 PKCS #1의 서명 규칙 안에서 관리됐다.

## 지금 무엇을 봐야 할까

- RSA 서명 구조: PKCS #1 v2.2, RFC 8017
- 해시 알고리즘 자체: SHA-2, SHA-3 등 해당 표준
- 인증서의 서명 알고리즘: X.509 프로파일과 사용 프로토콜

`PKCS #2`라는 이름의 오래된 구현을 새로 선택하면 안 된다. 문서에서 이 번호를 발견하면 역사적 문맥인지, 실제로는 PKCS #1의 최신 서명 방식을 뜻하는지 확인한다.

## 해시만으로 서명이 되지 않는다

해시는 비밀 키를 사용하지 않으므로 누구나 같은 값을 계산할 수 있다. 무결성과 서명자 확인을 위해서는 개인 키 기반 서명, 공개 키 검증, 인증서 신뢰 확인이 함께 필요하다.

## 현재 권장 관점

- 새 RSA 서명은 프로토콜이 허용한다면 RSASSA-PSS를 검토한다.
- SHA-1과 MD5 같은 오래된 해시를 새 서명에 사용하지 않는다.
- 알고리즘 이름뿐 아니라 해시·MGF(마스크 생성 함수)·salt 파라미터를 확인한다.
- 오래된 OID(알고리즘을 가리키는 숫자 식별자)와 문서 이름을 최신 규격으로 잘못 해석하지 않는다.

## 해시 값이 일치해도 작성자를 모르는 이유

다운로드 페이지에 파일과 SHA-256 값이 나란히 있다고 하자. 내가 계산한 해시와 페이지의 값이 같으면 **그 페이지가 제시한 파일과 같은 바이트를 받았는지** 확인하는 데 도움이 된다. 하지만 공격자가 파일과 표시된 해시를 모두 바꿀 수 있다면 악성 파일의 해시도 함께 게시할 수 있다.

따라서 해시 계산, 서명 검증, 서명 키의 신뢰 확인을 다른 단계로 봐야 한다. 해시는 데이터에서 계산한 값이고, 서명은 특정 개인 키를 이용한 연산이며, 인증서 검증은 그 공개 키를 누구의 것으로 받아들일지 판단하는 과정이다.

## 오래된 문서를 현재 구현으로 옮기는 순서

‘PKCS #2 호환’이라는 문구만으로 알고리즘을 선택하지 않는다. 실제 사용 중인 서명 OID와 해시를 확인하고, 메시지의 서명 대상 바이트를 파악한 뒤 현재 프로토콜이 허용하는 방식과 비교한다. 역사적 번호의 대응 관계와 현재 알고리즘의 안전성은 별도 문제다.

PKCS #2를 독립적으로 새로 구현하는 실습은 제공하지 않는다. 현재 RSA 서명 구조는 [PKCS #1]({{ '/pki/pkcs/pkcs1/' | relative_url }})에서, 서명과 콘텐츠를 함께 담는 구조는 [PKCS #7/CMS]({{ '/pki/pkcs/pkcs7/' | relative_url }})에서 이어 읽는 편이 실제 코드와 연결된다.

## 관련 문서

- [RFC 8017: PKCS #1 v2.2](https://www.rfc-editor.org/rfc/rfc8017.html)

{: .note }
PKCS #2 자체에 대응하는 최신 RFC가 따로 있는 것이 아니다. 폐기 후 관련 내용이 PKCS #1에 통합됐다는 관계를 이해하는 것이 핵심이다.
