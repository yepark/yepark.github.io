VID(Virtual ID)는 국내 전자서명인증체계에서 인증서 소유자의 식별번호를 인증서에 그대로 넣지 않고 본인 확인에 사용할 수 있도록 만든 가상식별번호다. EVID(Encrypted VID)는 인증서 발급 과정에서 VID 관련 정보를 인증기관에 안전하게 전달하기 위한 암호화된 값이다.

## VID 생성 개념

기술 규격은 식별번호 `IDN`과 난수 `R`을 해시 함수에 입력해 VID를 만든다. 규격 표현을 단순화하면 다음과 같다.

```text
VID = h(h(IDN, R))
```

난수가 함께 사용되므로 인증서에 저장된 VID만 보고 원래 식별번호를 바로 알 수 없게 설계됐다. 본인 확인 시에는 사용자가 제공한 식별번호와 개인 키 쪽에 보관된 난수로 VID를 다시 계산해, 인증서의 값과 같은지 비교한다.

## EVID가 필요한 이유

인증서 발급 요청 단계에서는 인증기관이 VID와 난수를 검증해야 한다. 이 정보를 평문으로 보내지 않고 인증기관의 공개 키로 암호화한 값이 EVID다.

```text
EVID = E(PK_CA, VID || R)
```

인증기관은 자신의 개인 키로 EVID를 복호화하고, 가입자 확인 단계에서 확보한 식별번호로 VID를 다시 계산해 일치 여부를 확인한다. 검증을 통과하면 규격에 따른 VID 정보가 인증서의 소유자 대체명칭 영역에 포함된다.

## VID와 EVID의 차이

| 구분 | VID | EVID |
| --- | --- | --- |
| 의미 | 가상식별번호 | 암호화된 가상식별번호 정보 |
| 주된 목적 | 인증서 기반 본인 확인 | 발급 과정의 기밀 전송과 검증 |
| 처리 | 해시 기반 비교 | 인증기관 키를 이용한 암·복호화 |

VID는 전자서명 값도 아니고 암호화 키도 아니다. EVID 역시 최종 사용자 인증서에서 항상 사용하는 일반 데이터라기보다 발급 프로토콜의 맥락에서 이해해야 한다. 실제 구현은 ASN.1 구조, OID, 해시 알고리즘과 저장 위치까지 해당 인증체계의 최신 규격을 따라야 한다.

## 본인 확인 흐름을 단계별로 보기

검증자는 인증서에 들어 있는 VID만으로 사용자의 식별번호를 알아낼 수 없다. 사용자에게 받은 식별번호와 개인 키 저장 영역에서 안전하게 꺼낸 난수 `R`이 함께 있어야 비교값을 만들 수 있다.

1. 인증서에서 VID 구조와 해시 알고리즘 식별자를 읽는다.
2. 사용자가 입력하거나 업무 절차에서 확보한 IDN을 준비한다.
3. 개인 키와 함께 보호된 난수 `R`을 가져온다.
4. 규격의 인코딩 순서대로 `IDN`과 `R`을 해시한다.
5. 계산한 VID와 인증서의 VID를 바이트 단위로 비교한다.

여기서 “문자열을 이어 붙여 해시한다” 정도로 구현하면 문자 인코딩, 길이, ASN.1 표현 차이 때문에 다른 결과가 나올 수 있다. 규격이 정의한 `HashContent` 구조와 DER 인코딩을 그대로 따라야 상호 운용된다.

## 보안 경계

- 난수 `R`은 공개 정보가 아니며 개인 키와 같은 수준으로 보호해야 한다.
- VID 일치 여부는 식별번호 확인 결과일 뿐, 인증서의 전자서명 검증을 대신하지 않는다.
- 인증서 신뢰 체인과 유효 기간, 폐지 상태를 먼저 검증해야 한다.
- 비교 실패 원인을 외부에 지나치게 자세히 노출하지 않는다.
- 신규 시스템은 해당 업무에 VID가 정말 필요한지, 더 최신의 본인 확인 수단이 있는지도 검토한다.
